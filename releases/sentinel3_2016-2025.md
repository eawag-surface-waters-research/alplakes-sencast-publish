# Sentinel-3 water quality maps for 53 European perialpine lakes (2016–2025)

## Abstract

This dataset provides satellite-derived water quality maps for 53 lakes in and around the European Alps, from April 2016 to December 2025, as one CF-compliant NetCDF file per lake. Each file is a time series of 300 m maps, one per Sentinel-3A/B OLCI overpass, of chlorophyll-a (OC3), total suspended matter (Binding 754 nm), Secchi depth (Lee) and the Forel-Ule colour index. The maps were produced operationally with the Sencast processing toolbox (IDEPIX pixel classification, adjacency correction, POLYMER atmospheric correction) for the Alplakes platform, and then combined per lake into NetCDF time series. The dataset supports studies of spatial patterns, seasonal dynamics and long-term trends in lake optical properties across the region.

## Overview

This dataset has satellite water quality maps for 53 lakes in and around the Alps, one NetCDF file per lake. Each file is a time series of maps, one map per Sentinel-3 overpass, from April 2016 to December 2025. There are four products:

- chlorophyll-a
- total suspended matter
- Secchi depth
- Forel-Ule colour index

The maps were made with [Sencast](https://github.com/eawag-surface-waters-research/sencast) from Sentinel-3 OLCI imagery. They are the same data shown on [Alplakes](https://www.alplakes.eawag.ch).

## Quick start

```python
import xarray as xr

ds = xr.open_dataset("netcdf/geneva.nc")

# Map of chlorophyll-a for one date
ds.chla_oc3.sel(time="2023-07-15", method="nearest").plot()

# Lake-wide median chlorophyll-a over time, only overpasses where at least 50% of the lake is valid.
# The grid is a bounding box that includes land, so measure coverage against the lake mask
# (pixels that are valid at least once), not against the whole grid.
lake_mask = ds.chla_oc3.notnull().any("time")
coverage = ds.chla_oc3.notnull().sum(["lat", "lon"]) / lake_mask.sum()
ds.chla_oc3.median(["lat", "lon"]).where(coverage > 0.5).plot()
```

## File structure

Each `{lake}.nc` file follows CF-1.8:

```
Dimensions:  time, lat, lon
Coordinates:
  time       (time)            acquisition time, UTC
  lat        (lat)             pixel centre latitude, degrees_north (decreasing, north to south)
  lon        (lon)             pixel centre longitude, degrees_east
  satellite  (time)            "S3A" or "S3B"
Variables:
  chla_oc3        (time, lat, lon) float32
  tsm_binding754  (time, lat, lon) float32
  secchi_lee      (time, lat, lon) float32
  forel_ule       (time, lat, lon) float32
  spatial_ref     ()               CRS definition (WGS 84, EPSG:4326)
Global attributes: title, lake, Conventions, source, sencast_commit, sencast_docker_image,
                   date_created, history, geospatial_lat_min/max, geospatial_lon_min/max,
                   time_coverage_start, time_coverage_end
```

- **Grid:** regular latitude/longitude grid in WGS 84. Pixels are about 0.0037° (longitude) × 0.0027° (latitude), roughly 300 m × 300 m, matching the OLCI full-resolution pixel. Each lake has its own grid, cropped to the lake.
- **Time:** one step per Sentinel-3 scene that produced at least one product for the lake. Overpasses are between about 09:00 and 11:00 UTC. Sentinel-3A data start in 2016 and Sentinel-3B data in 2018. The `satellite` coordinate says which satellite each step came from. Two steps can be less than a minute apart:
  - **2018 tandem phase:** from May to October 2018, Sentinel-3B flew about 30 seconds behind Sentinel-3A. Many lakes have an S3A and an S3B step about 30 s apart in this period (689 pairs over all lakes). They are separate observations.
  - **2025-09-04 in `geneva.nc` and `neuchatel.nc`:** the two Sentinel-3B steps at 10:26:52 and 10:26:59 are two processings of the same overpass. They cover almost the same pixels and their values differ by 1–3%. Use only one of them when counting observations.
- **Missing values:** `NaN` (`_FillValue = NaN`) marks pixels with no valid value: pixels outside the lake outline, shallow/near-shore water (lake mask), cloud, and pixels failing the quality criteria described under [Processing](#processing). Many time steps are mostly or entirely cloud-covered, and about 2,000 time steps per variable (over all lakes) have only one valid pixel. Filter on the fraction of valid pixels before computing lake-wide statistics.
- **Compression:** zlib level 4, chunked as (up to 100 time steps, full lat, full lon).

## Variables

| Variable         | Description                                  | Units          | Sencast product                 | Valid range | Typical range (Lake Geneva, 5th–95th percentile) |
|------------------|----------------------------------------------|----------------|---------------------------------|-------------|---------------------------|
| `chla_oc3`       | Chlorophyll-a concentration, OC3 algorithm   | mg m-3         | `OC3_chla`                      | 0 – 1000    | 1.5 – 7.2                 |
| `tsm_binding754` | Total suspended matter, Binding 754 nm       | g m-3          | `COMBINE_tsm_binding754`        | 0 – 1000    | 0.4 – 1.7                 |
| `secchi_lee`     | Secchi depth, Lee et al. algorithm           | m              | `SECCHIDEPTH_Zsd_lee`           | 0 – 25      | 3.9 – 10.1                |
| `forel_ule`      | Forel-Ule water colour index (integer 1–21)  | 1              | `FORELULE_forel_ule`            | 0 – 22      | 4 – 6                     |

The valid range is the range Sencast keeps when writing the GeoTIFFs (set in the `[GEOTIFF]` section of `alplakes_s3.ini`); values outside it are set to NaN. The Forel-Ule scale runs from 1 to 21, so treat `forel_ule = 0` as invalid. It occurs in 6 pixels: `garda.nc` 2023-04-08, `greifensee.nc` 2020-03-18, `lugano.nc` 2020-01-19 and `zurich.nc` 2017-02-16.

Each variable's `source_product` attribute gives its Sencast product name, and `chla_oc3`, `tsm_binding754` and `secchi_lee` also have a CF `standard_name`. For algorithm details and validation, see the [Sencast documentation](https://github.com/eawag-surface-waters-research/sencast).

## Limitations

- **Small lakes:** at about 300 m resolution, small lakes (e.g. Bled, Pfäffikon, Silvaplana) are only a few pixels across. Pixels near the shore can be affected by adjacency effects from land.
- **Clouds:** coverage is uneven. Winter and cloudy periods have far fewer valid observations, and the number of time steps varies a lot between lakes.
- **Estimates, not measurements:** all products come from the satellite signal using general algorithms, not lake-specific ones. Absolute values should be checked against in-situ data before quantitative use.
- **Very low values:** values close to zero are most likely algorithm artefacts rather than real concentrations. 3,361 `tsm_binding754` values and 16 `chla_oc3` values are below 0.01.

## Processing

### 1. Sencast

The scenes were processed operationally for Alplakes with [Sencast](https://github.com/eawag-surface-waters-research/sencast) in the Docker image `eawag/sencast:0.2.0`, using the parameter file [`alplakes_s3.ini`](https://github.com/eawag-surface-waters-research/sencast/blob/d797620940c82a8046b95f1ab268199ef9314350/parameters/alplakes_s3.ini) included in this package. The Sencast commit that processed each scene is recorded in the Alplakes scene metadata:

| Sencast commit | Share of scenes |
|---|---:|
| [`d797620`](https://github.com/eawag-surface-waters-research/sencast/tree/d797620940c82a8046b95f1ab268199ef9314350) | 94.6% |
| [`332567b`](https://github.com/eawag-surface-waters-research/sencast/tree/332567b18e6fc51b7d61afc893508c71390826ba) | 3.2% |
| [`a3d7641`](https://github.com/eawag-surface-waters-research/sencast/tree/a3d76416a5c3f5e1519e46216041553af29699d7) | 2.2% |

The three commits use the same parameter file and the same processor code for the four products in this release. They differ only in the code that downloads the input data, and in primary production, which is not included. The parameter file on Sencast's `master` branch has since changed (from commit `3d581e8` onwards), so use the version in this package.

Processing chain, at 300 m resolution:

1. **IDEPIX:** pixel classification (cloud, land, snow/ice, etc.).
2. **RADCOR:** adjacency-effect correction, with Sencast's default settings.
3. **POLYMER:** atmospheric correction with the `PR05` water model and NASA ancillary data.
4. **COMBINE:** combines the IDEPIX and POLYMER outputs. A pixel is valid only if `pixel_classif_flags == 0 and vza < 25`, i.e. IDEPIX found no cloud or other flag, and the viewing zenith angle is below 25°. Total suspended matter (Binding 754 nm) comes from POLYMER through this step.
5. **Products** from the COMBINE output:
   - **OC3:** chlorophyll-a
   - **SECCHIDEPTH:** Secchi depth (Lee), with `m0 = 0.0`, `m1 = 5.8`
   - **FORELULE:** Forel-Ule colour index
6. **GeoTIFF export** over the Alpine region, with the `shallow_300` lake mask (removes shallow and near-shore pixels) and the valid ranges listed under [Variables](#variables).

### 2. Cropping per lake

The regional GeoTIFFs were cropped to each lake with [alplakes-sencast-metadata](https://github.com/eawag-surface-waters-research/alplakes-sencast-metadata/tree/550083c). The cropped files were regenerated for the whole period on 2026-09-21. For each lake outline in the Alplakes lake polygons (`lakes.geojson`):

- The GeoTIFF is cut to the polygon's bounding box, on the original pixel grid. There is no resampling.
- Pixels whose centre lies outside the polygon are set to NaN.
- A scene is skipped for a lake if no pixel inside the polygon is valid. This is why the number of time steps differs between lakes and products.

### 3. Conversion to NetCDF

The cropped GeoTIFFs were combined into one NetCDF per lake with the conversion code in `code.zip`, in the conda environment listed in `releases/sentinel3_2016-2025.lock.txt` (Linux 64-bit):

```bash
conda create -n sencast-publish --file releases/sentinel3_2016-2025.lock.txt
conda activate sencast-publish
python scripts/main.py --sensor sentinel3 --sync --end 2025-12-31 --overwrite
```
